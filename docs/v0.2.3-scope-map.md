# v0.2.3 complete repair and opportunity map

Consolidated 2026-10-24 after the user stopped the Windows audit. This is the authorized complete release scope, not a priority shortlist or a claim that every item is already verified. See [implementation coverage](v0.2.3-implementation-coverage.md) for build evidence and remaining qualification. Caliper, its benchmark controller and owned inference/preview processes are stopped; the observation automation was deleted. This document does not authorize restarting them or publishing. The [execution plan](v0.2.3-execution-plan.md) translates all fourteen categories into dependency-based work packages and acceptance evidence.

Every recorded issue needs a disposition and evidence. An open defect requires repair and regression; an uncertain cause requires focused diagnosis followed by the smallest supported repair; an earlier local or released fix requires retention and relevant requalification. Expected refusals and withdrawn allegations remain explicit non-defects. A generated-game failure supplies a general harness lesson and regression case, not a promise to ship a game-specific feature in Caliper.

## Development contract for every item

Apply all eleven [development principles](development-principles.md): simplicity/lightness; offload model work; treat bloat as a defect; structured current-step interaction; GraphQL/Kuzu as the shared foundation; consistent instructions; small-model-friendly tools; exact useful help; evidence over claims; host-owned mechanics; and measured total burden. These constrain implementation, not another checklist injected into model context.

Use existing tools, PAT, graph, check receipts and lifecycle infrastructure. Preserve one-field-at-a-time PAT. Replace redundant instructions rather than append another review layer. No new reviewer, mandatory full-project inventory, giant tool schema, background whole-tree scan, embedding service or speculative cache/index. Preserve user intent, configuration, graph history, ownership and authorization during recovery.

## 1. Input fidelity and usable tool contracts

**Scope:** INPUT-001, INPUT-002, ASK-001, NATIVE-001, MODEL-003, MODEL-004; failure-map F04 timeout-limit observation.

- Preserve the exact submitted prompt through Windows terminal input: multiline paste, paragraph breaks, CRLF/LF, blank lines, punctuation and Unicode paths. Flattened paragraphs and ASCII substitution were workarounds, not fixes.
- Replace ambiguous comma-delimited answer choices with an unambiguous supported contract. Natural option labels may contain commas; real options, free text and returned answers must remain associated with the actual question/call.
- Keep strict rejection of duplicate JSON keys and ambiguous calls. Give a bounded correction opportunity for a provably unexecuted call instead of terminating the entire run. Never select an arbitrary duplicate value, replay uncertain effects or silently discard authored fields.
- Make timeouts and other actual limits agree across native schemas, help, examples and enforcement. The observed 1200-second request exceeded a 600-second limit; give the exact legal correction.
- Favor grounded read/edit contracts over fragile shell string replacement. Preserve current read-hash checks, report a missing replacement target as failure, and make recovery clear. Probe examples should inspect actual data shapes and avoid circular-object serialization assumptions.

**Closure evidence:** real Windows PTY roundtrips, matching ask-result receipts, malformed-call correction without effects, boundary-value tool tests, and failed/stale edits that cannot report success.

## 2. PAT structure, execution scope and repair continuity

**Scope:** BENCH-001, BENCH-002, PAT-003, PAT-004, PAT-005, PAT-006, PAT-007, PAT-008, PERF-004, PERF-005, BENCH-005, TEST-001.

- Align the actual machine-visible plan contract with the current question. The 24-field advertised schema and silent dropping of newly authored future fields must go. Preserve one-field progression; reject out-of-phase answers before mutation with an exact next action.
- Make draft, readiness, preparation, claim, focus, execution and settlement consistent. Return real IDs and legal actions; the model should not reconstruct ownership or guess IDs. Retain the local direct-claim/focus repair and fail closed on stale or unrelated claims.
- Stop repeating strategy, acceptance, proof and reviewer prose across every field and receipt. Reference saved graph data and carry deterministic state in the host.
- Permit a coherent first increment before detailing unrelated future tasks. Make its necessary check infrastructure available in that increment; do not require a future task to supply today's acceptance command. Avoid broad implementation under an unrelated task merely to keep moving.
- Recover from infrastructure failures with the current frozen brief, valid evidence and correct owner instead of requeue/rebrief/readiness loops when nothing relevant changed.
- Support repair of newly contradicted qualified work through the existing task lifecycle. Preserve the original receipt and expose the need for repair; do not force a defect into the next unrelated task or invent another workflow tool.
- Distinguish actual progress from many successful but inconclusive numerical probes. Reuse relevant evidence and convert useful exploration into durable assertions; do not add an arbitrary turn/time cutoff or another judge loop.
- Make context-setting/resume semantics explicit: what changes next request versus next run, and how selection/claim are retained. Prevent accidental tool-mode changes from being mistaken for model failure.

**Closure evidence:** the recorded phase-error sequences replay without silent loss; direct and guided claims converge on the same owner; unchanged-work recovery preserves state; counterevidence can reopen repair safely; measured planning calls/bytes and time to useful output improve without weaker requirements.

## 3. User steering, interruption and recovery

**Scope:** RUN-001, BENCH-005, ENV-001; related controller issues in section 11.

- Repair `/btw` and task-comment persistence across running, interrupted and settled ownership states. A captured `btw` trace event precedes persistence and cannot count as delivery.
- Acknowledge committed delivery, retain undelivered intent visibly, and resume only with a valid actual owner. User feedback must not itself manufacture execution authority. Preserve ordering and exactly-once application.
- Cover `/comment`, stop/retry/resume and session adoption without duplicating requests or dropping current work. Reconcile old and new receipts instead of trusting stale status.
- Handle sleep/network inactivity as environment interruption, not fabricated model completion. Preserve recovery state and account separately for suspend time; do not alter power policy or retry an unchanged known-failing compaction indefinitely.

**Closure evidence:** feedback before/during/after settlement, persistence refusal and interrupted recovery retain text and apply it once; process/session state distinguishes active, waiting, stopped and failed.

## 4. Context, compaction and long-session performance

**Scope:** BENCH-003, D1-003, PERF-006, PERF-004, PERF-005; earlier metrics and Luna admission records.

- Budget the actual encoded judge request before paying for summary generation. The observed compaction generated a summary for about 212 seconds and then failed the 64 KiB client-side limit before judge inference.
- Replace all-history protected-anchor/call-ID expansion with a bounded projection of current essential intent, ownership and evidence, while preserving original records in host storage. Exact deduplication alone is not a size bound.
- Reuse a valid generated candidate on recoverable judging failures. Preserve original context if compaction cannot safely apply; report the real recovery path. Do not blindly accept summaries, silently truncate protected facts or merely raise the byte cap.
- Bound admission retries and reduce optional evidence efficiently. Separate serialization/admission work from model inference in diagnostics.
- Investigate adjacent-request prefix changes, cache/slot reuse and repeated prefill. Large context capacity does not guarantee fast follow-ups. Preserve a stable reusable prefix where possible and remove repeated consumed material through existing context mechanisms.
- Measure active time, first useful artifact, prefill/reused tokens, decoding, request latency distribution, calls, bytes, memory, compaction and recovery effort. Exclude standby/waiting and disclose assistance; retain estimates as estimates.

**Closure evidence:** escaped and boundary-size payloads, long histories and repeated compaction failure do not lose intent or enter expensive retry loops; compare matched long-session requests and output quality, not just maximum context size.

## 5. Decision judge: justify every remaining role

**Scope:** D1-001, D1-002, D1-003, BENCH-003, CONFIG-001.

- Enumerate advisory progress/discovery, readiness/coherence, authorization, style advice and compaction separately. Their contracts differ; turning the entire judge off currently changes required admission behavior.
- Remove or sharply narrow routine advisory calls that repeat host-known phase/readiness facts. Use deterministic state for deterministic decisions. Retain model judgment only where evaluation demonstrates useful incremental judgment.
- Track newly delivered comments for scheduling instead of treating all retained historical comments as new on every successful step. Preserve the comments themselves.
- Qualify slow, unavailable, busy, expired, low-confidence and malformed judge responses. Advisory outages must match the documented continuation behavior; required decisions must expose an honest recovery path without invented approval.
- Compare reduced-advisory and existing behavior on retained evidence and controlled configurations: real defects caught, false interventions, useful changed actions, latency, tokens, memory and final quality. The observed advisory interval was about 7m32s for 141 calls at an interim checkpoint; this is not demonstrated net benefit or a precise promised saving.
- Retain independent runtime/protocol configuration, exact System One choice/probability interpretation and compatible defaults. Catalog availability is not successful inference or residency.

**Closure evidence:** one old comment cannot retrigger every judgment; new steering still receives attention; all remaining judge dependencies have explicit benefit/behavior evidence. Full judge removal remains an evidence-led design decision, not a claim already settled.

## 9. Verification that matches the claim

**Scope:** BENCH-006, BENCH-007, QA-001, QA-002, QA-003, QA-004, QA-005, VERIFY-001, MODEL-005; OQR:QA-003/004 and Luna's earlier check findings.

- Run both already-configured independent checks when one fails; the first failure must not suppress unrelated diagnostic coverage. Respect genuine dependency or cancellation rather than adding another check tier.
- Use representative real input for a claimed user path. Include hit-testing, overlays, keyboard/focus and transition outcomes where relevant.
- Preserve meaningful behavioral constraints and negative controls. Distinguish a wrong fixture/oracle from a product defect; changing a threshold needs an actual design reason, not merely a green result.

- Ground diagnoses in observed failing behavior before recording causal explanations. Correct PAT/graph/handoff notes when the cause changes. Bind final completion presentation to actual host settlement and disclose remaining coverage.
- Reuse current valid checks; repeat only when code, requirements, evidence or environment meaningfully changes. This improves existing verification rather than creating extra review layers.

**Closure evidence:** deliberate failed pipelines, missing browsers, skipped tests, occluded controls, stale receipts, changed thresholds and paired-check failures produce truthful distinct outcomes. The model is given the exact next recovery step.

## Release closure and exclusions

All areas above belong to the v0.2.3 scope. Consolidation does not mean every incident needs a separate mechanism: one root-cause repair can close several records only when the relevant regressions demonstrate it. Maintain per-item evidence, cause confidence, implementation state and acceptance results; do not close an uncertain item merely by adding a paragraph to a guide.

Validate focused regressions and appropriate package/platform checks, then the actual packaged candidate and advertised flows. A subsequent user-authorized harness benchmark should measure spontaneous knowledge use, PAT usability, recovery, judge cost/benefit, truthful verification and total burden, with Luna using real harness controls. The game is a workload and bounded evidence source, not the objective. Preserve baseline versus changed configurations and assistance attribution. No claim of perfection or universal model reliability follows from one run.

Excluded v0.3.0 product scope: reusable workflow builder, build-a-block tooling, machine-wide workflow library, user enable/disable system for custom workflow tools, and tool-definition generation from those blocks. Excluded as independent objectives: polishing/expanding Space Transporter, new reviewers, new mandatory review layers and speculative infrastructure. Reliability/design/graph work described above remains included even where an older document originally mentioned it under v0.3.0.
