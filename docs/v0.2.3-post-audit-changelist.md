# v0.2.3 post-audit changelist

This is the corrective changelist for the tested v0.2.3 candidate, not a list of completed or shipped changes. It retains the fourteen categories in the approved scope and incorporates the Windows audit closeout. It is not a priority shortlist. The v0.3.0 workflow-builder/library remains excluded.

The [failure map](v0.2.3-failure-map.md) and [append-only ledger](../../test-findings/failure-ledger.jsonl) retain the evidence, causal limits, repair and regression criteria for all 175 historical and current issue IDs. That total includes historical fixes, opportunities, model/artifact problems and test-infrastructure failures; it is not a count of new product defects. The [coverage matrix](../../test-findings/v023-user-feature-coverage.md) retains failed, partial and deferred qualification separately.

## 1. Input, questions and native tool contracts

- Retain the observed multiline/Unicode and comma-containing option improvements; complete relevant real Windows input coverage.
- Produce exactly one reserved “None of the above” option. Make skip, optional comments and whole-question-batch cancellation unambiguous, preserving answer/call ownership and the prior composer.
- Keep native schemas, legal limits, help examples and recoverable errors consistent. Correct provably unexecuted malformed calls without replaying uncertain effects or silently dropping authored fields.
- Repair the Windows shell transport that corrupts quoted-heredoc backslashes. Keep this separate from external terminal-capture corruption.

**Acceptance:** exact prompt/answer bytes and associations survive the real transport; cancellation has the stated scope; malformed calls cause no effects; quoted source arrives intact. Includes ASK-001–004, INPUT-001/002, NATIVE-001 and WIN-014.

## 2. Turn intent, PAT and workflow completion

- Carry the authorized turn scope through existing admission and finalization. A question, preference, plan-only request or status inspection must not trigger implementation or a host check.
- Separate successful status retrieval from the qualification of the work being inspected. Reading unfinished work must neither register an execution obligation nor fail an otherwise completed answer.
- Preserve one-field PAT progression, real IDs, frozen ownership and legal next actions. Reduce repeated planning prose and permit coherent increments without detailing unrelated future work.
- Repair draft-task feedback, readiness decision recording, recovery/retry and contradicted-work repair through existing lifecycle mechanisms. Present structured plans and readiness briefs as readable fields while retaining the exact stored data.

**Acceptance:** planning/reporting turns settle correctly with no execution; actual coding still requires current valid evidence; stale claims fail; readiness deny/cancel is durable and cannot dispatch. Includes SCOPE-002/003, PAT-009–015 and earlier PAT/BENCH scope findings.

## 3. Feedback, interruption and recovery

- Make feedback submission, durable owner persistence and model uptake distinct visible states.
- Preserve pending interjections through reviewer activity, interruption and restart; never silently lose them or call a trace event successful delivery.
- Retain exact-once ordering, current prompt/workspace identity, tool exposure and relevant selection/claim state during supported recovery.
- Distinguish stop, cancellation, environment interruption, controller exit and model completion; do not resend from stale receipts.

**Acceptance:** feedback reaches its intended owner once across the recorded boundary cases; failed persistence remains visible; recovery creates no duplicate run. Includes RUN-001, RESUME-001 and linked lifecycle findings.

## 4. Context and compaction

- Validate both encoded request capacity and native token limits before expensive work where possible; classify capacity refusals consistently.
- Keep protected intent, ownership and evidence bounded through an existing host-owned projection, with complete originals retained outside the active prompt.
- Reject vacuous summaries, preserve original context when compaction fails, reuse valid candidates and prevent repeated unchanged summary attempts.
- Stabilize reusable request prefixes and distinguish actual inference, admission/reduction work, cache reuse and waiting.

**Acceptance:** byte/token boundary and semantic-retention fixtures preserve essential facts, avoid expensive retry loops and report honest recovery. Includes CTX-003, D1-003, BENCH-003 and PERF-006.

## 5. Judge usefulness and cost

- Remove or narrow routine advisory judging of successful inspection and host-known bookkeeping; preserve separate authorization, readiness and verification contracts.
- Distinguish schema/admission refusal, executed failure, expected negative results and successful observations before offering repair advice.
- Do not let intentional bounded output or old comments repeatedly reactivate unnecessary advice. Retain meaningful new evidence and failure handling.
- Preserve optional provider usage in existing verdict/trace records. Missing usage stays unknown. Measure useful interventions, false corrections and elapsed cost separately for each judge role.

**Acceptance:** the recorded false-repair sequences disappear without weakening real refusal handling; successful read-only work avoids repeated bookkeeping judgments; usage-present/absent cases remain truthful. Includes D1-001–006 and PERF-007.

## 6. Graph, memory and durable knowledge

- Improve deterministic recall relevance so generic words, prohibited-action clauses and incidental paths do not qualify unrelated notes.
- Preserve compact historical provenance and locators under the recall budget; do not present a remembered note as a new user instruction.
- Update design/project identity without replacing still-valid preferences with a feature-only summary. Preserve versions and explicit scope.
- Align GraphQL help and introspection with the actual role-visible schema, including returned fields and legal roots.
- Repair Kuzu checkpoint/rollback handling and preserve reliable ownership, history and recovery around failures.

**Acceptance:** relevant and irrelevant recall controls distinguish correctly; model attribution is accurate; identity updates retain valid preferences; real graph errors remain recoverable and visible. Includes GRAPH-008–013 and prior graph/access findings.

## 7. Design identity and application

- Retain concise preference elicitation and identity storage/retrieval, then verify application to the actual output.
- Connect existing guidance to purposeful layout, typography, hierarchy, responsive behavior, keyboard access and useful motion.
- Qualify style propagation across coding, worker and reviewer roles; distinguish spontaneous uptake from directed tests and recall-assisted conformance.
- Report the current visual-inspection limitation truthfully; a screenshot file or DOM string is not evidence of visual review.

**Acceptance:** observed output reflects the saved identity and relevant user controls work. No universal aesthetic template or additional design-review agent.

## 8. Capabilities, architecture and coherent increments

- Keep concise graph links between requested behavior, its actual implementation owner, callers and acceptance evidence.
- Distinguish planned, implemented and verified capabilities. Unsupported controls must not masquerade as implemented features.
- Reconcile actual state/persistence/unit owners with architecture notes. Use relevant slices rather than mandatory whole-project inventories.
- Deliver coherent increments whose required check infrastructure exists in the same increment.

**Acceptance:** feature claims lead to real behavior and current evidence; architecture notes identify actual owners; incomplete features remain explicit.

## 9. Checks and independent review

- Expose advertised checks in the actual worker registry and align schema/help/request transmission.
- Bind checks to the correct task, attempt, revision and runtime. Honor permitted timeout policy and make incomplete, skipped and failed checks distinct.
- Prevent missing required prerequisites from producing qualification through exit-zero skip behavior.
- Enforce reviewer read-only authority before effects, preserve receipt validity, and reject unsupported reproduction claims or incomplete verdicts.
- Repair misleading oracle/test claims with positive, negative and real-entry-point evidence.

**Acceptance:** skipped browser coverage cannot qualify a browser requirement; reviewer writes cannot invalidate the artifact after claimed verification; reported checks are traceable to actual execution. Includes WORKER-001, REVIEW-001/002, QA-005 and existing check/receipt findings.

## 10. Windows, configuration, model services and distribution

- Fix CONFIG-002: save explicit `disabled: false` so a personal true value cannot silently return on project reload. Preserve genuinely omitted-field inheritance and runtime/protocol compatibility.
- Correct misleading catalog/saved/resident/selected labels; keep connectivity, configuration, loading and inference separate.
- Retain owned-service lifecycle improvements and qualify cancellation, runtime/cwd/path identity and cleanup without killing unrelated services.
- Finish distribution-specific diagnosis and qualification in suitable isolation: clean install, startup, update cancellation/activation, rollback, PATH/version convergence and uninstall.

**Acceptance:** live and reloaded effective configuration agree; model states describe real evidence; package flows preserve user configuration and have recoverable failure behavior. No Windows security changes.

## 11. Observation, accounting and evidence storage

- Retain atomic numbered input, committed-delivery checks and dead-owner recovery gates in the test controller.
- Repair external Unicode capture at its first decoding boundary; preserve incomplete UTF-8 suffixes rather than merely increasing read size. Keep this controller/dependency issue separate from product rendering.
- Fix sharing-related evidence publication and stale-state handling while keeping observations bounded.
- Distinguish coding, review, judge, compaction and wait costs. Keep raw evidence in TEMP and preserve stable locators in durable reports.

**Acceptance:** mixed UI traffic cannot wedge the queue; concurrent capture does not kill the controller; Unicode boundaries survive; measurements retain provenance and do not invent billing. Includes CTRL-009/011 and audit/controller findings.

## 12. User-facing UI and advertised flows

- Derive `/tools` display from the actual active registry.
- Make current alerts reflect current outcomes; preserve valid drafts on validation errors and make `/clear` explicitly view-only.
- Deduplicate staged/saved Setup models through one canonical identity and preserve the actual selection.
- Fix CRLF text rendering, task-detail scroll resets, empty/filter messages and raw structured-data presentation.
- Make file/diff truncation and omitted lines explicit, detect relevant edits beyond captured prefixes, and preserve capture ID/time/hash with comments.
- Repair the Diff comment shortcut so it has the correct captured viewer/owner context.

**Acceptance:** each repaired flow is exercised through discover/open, action, result, return and restoration—not merely opening a tab. Includes UI-001–018; prior passing slices remain retained evidence.

## 13. Consistent instructions and configuration snapshots

- Use authoritative role/phase contracts for tool names, limits, lifecycle terms, legal actions and evidence rules.
- Verify actual assembled requests for ordinary coding, planning, workers, reviewers, decisions, compaction and recovery.
- Remove contradictory or redundant instructions instead of appending another checklist.
- Preserve user customizations, admitted prompt/style snapshots and explicit next-request/next-run behavior.

**Acceptance:** help examples are callable under the stated role; emitted schemas and enforcement agree; upgrades and retries do not silently substitute rules.

## 14. Code-and-trace feedback into the harness

- Retain every generated-code finding as a general regression or empirical acceptance case, including persistence transactions, repeated rewards, alternate transitions, bounded consumers, unit consistency and missing prerequisites.
- Correlate actual source revisions with model writes, guidance retrieval, checks and claims. Do not infer haste or harness causality without evidence.
- Prefer existing owner guidance, coherent increments and narrow behavioral/negative controls over more prose, universal scanners, new tools or a new review tier.
- Recheck artifact outcomes independently after harness repairs; do not patch the benchmark behind the model.

**Acceptance:** cases such as CODE-023 repeated empty-dock rewards and QA-005 skipped browser tests cannot support the same broad success claims. Removal of an old implementation pattern is not proof of overall game quality.

## Completion contract

Each mapped item ends in an explicit disposition: implement and regress; diagnose then implement; retain/requalify an existing fix; or document a justified non-defect/deferment. No item disappears because its category received a feature.

For each code change, reproduce the failure at the existing owner, make the smallest repair, run a meaningful regression including an adverse boundary, and verify the relevant live user flow when applicable. Compare request size/calls/latency where reducing burden is the goal. A component pass, model response or local patch alone is not shipped qualification.

Retain the measured gains from this candidate: exact multiline/Unicode submissions, comma-safe ask options, demonstrated executor feedback commit/uptake, owned-service behavior and bounded CLI/UI flows. Do not rebuild those mechanisms unless a remaining failure requires it.

Real model lifecycle, package installation/update/rollback, other platforms and remaining matrix routes are validation work, not presumed code defects. They stay explicit until tested. Publishing, installing, changing active inference or restarting the benchmark is not authorized by this changelist.
