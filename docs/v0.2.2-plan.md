# v0.2.2: reliable execution and useful project knowledge

Approved scope, 2026-10-24. Improve the existing graph, prompts and execution paths for small local models. No workflow builder, additional reviewer, new model-facing tool family, mandatory full-project inventory, or replay of Space Transporter. v0.3.0 owns reusable workflow authoring.

## Contracts

- One instruction source: embedded and distributed prompt catalogs agree; help, tool descriptions, guided questions and reviewer instructions use the same names and authority rules.
- Knowledge describes implementation; it never proves correctness or grants execution authority. User requirements override default design preferences. Project decisions and Caliper defaults have different names and provenance.
- Read only relevant knowledge sections. Update affected entries when meaning changes; reuse known current IDs. Do not create documentation for every symbol or repeat the full graph after every edit.
- Use existing PAT verification to test the promised behavior, resource/state invariants and actual UI where relevant. No additional review pass or agent is introduced.
- Code anchors include a project-relative path and recorded file fingerprint. Freshness means unchanged source, not verified behavior. Broken/missing references and unknown freshness remain explicit.
- Bound graph query rows, bytes, depth and page size. Search project assets, never the entire machine. Preserve project isolation, immutable versions, CAS and migration compatibility.

## Knowledge representation

Extend the existing Knowledge surface and immutable MemoryEntry versions. Markdown headings provide stable section anchors; keyword search returns selected sections and document identity. Typed references connect document keys/versions; the same bounded query can follow references in either direction. Explicit file anchors point into code and record a host-computed fingerprint when the document is appended. No speculative semantic index, embedding model, background whole-tree scan or automatic claim of completeness.

Default guide is bundled once and exposed through the knowledge surface with Caliper ownership; project writes cannot overwrite that namespace. Project identity, capabilities and architecture remain editable project knowledge. Detailed documents are optional expansions of compact map entries. Existing styleguide/user rules remain supported; do not silently replace them.

## Design research method

Record direct post links, author/platform, retrieved date, observed complaint, disagreement and access quality in a developer-only research document. Reddit/X opinions are qualitative examples, not evidence of prevalence or a reliable AI detector. Distill them into practical instructions: choose a product-specific identity; justify hierarchy and decoration; prefer real content; remove inert controls; verify keyboard and responsive states. Do not ban fonts, gradients or component libraries universally. Distinguish cultural style tells from functional/accessibility requirements. Do not distribute long posts or embed research logs in model context.

## Implementation record

Implemented on `codex/v02-graph-reliability`. Version metadata is 0.2.2; publication and the installed HP version have not been changed.

- Task claims return task focus through the existing durable handoff; failed claims preserve focus.
- Windows Bash resolves a native shell instead of System32/WSL; bash/check share resolution and pipeline failure propagation. Startup uses that resolver. Git Bash normalizes CRLF script text; write/edit remain byte-exact file tools.

- The tool guide, coding requirements and existing reviewer use consistent knowledge/evidence language. Git's plain-file prompt aliases on Windows resolve to the canonical YAML without duplicating instructions.
- Additional root causes fixed: Windows separator handling in discovery, and incompatible inherited decision protocol when a project switches runtime.

## Approved development-principle audit follow-up — 2026-10-24

The [development principles](development-principles.md) now include evidence over claims, host-owned mechanics and measuring total burden. They constrain development; they are not another model checklist.

The approved five changes are implemented locally:

1. Both ordinary coding and claimed-task coding compose the same short knowledge instruction. Passed checks are reusable only when host receipts identify them as current for that task and attempt; missing/stale checks remain required. The guide bodies stay on demand.
2. Basic GraphQL help leads with find, read-section and update examples. Advanced lifecycle and reference/freshness recipes are separate help topics. The generated knowledge template includes a keyword, a small limit and useful returned fields. The rendered basic help decreased from 10,667 to 3,212 bytes; callable examples are schema-tested.
3. Knowledge maintenance means updating one relevant entry after a meaningful capability or architecture decision changes. Link existing detail, split only when useful, and avoid per-edit documentation. The same language appears in help and standards.
4. [Measured retrieval work](knowledge-performance.md) exposed needless target reads. Selection-aware reference status and per-call target reuse cut the 10,000-note 32-link metadata sample from 326ms to 12.3ms, without changing output or introducing a new cache/index/tool.
5. Windows qualification now uses real directory junctions. This exposed and repaired a physical-path boundary defect: the platform's normal symlink resolver did not resolve junctions. A small shared native handle resolver now establishes consistent identity without scanning directories. Existing histories previously split through aliases remain preserved; no automatic merge is attempted. Privilege-dependent file-symlink coverage is reported separately.

New regression checks exercise assembled coding contexts, progressive help, aliases/fragments, reference source budgets, and real junction containment/identity. The full Go suite and final platform checks precede the fresh Space Transporter benchmark. Its initial prompt is preserved, its workspace is separate from the previous game, its context is 262,144, and its simulated user is explicitly gpt-6-luna. [The observed-run controller](observed-benchmark.md) records sent versus trace-confirmed input separately and keeps raw output in TEMP.

Iteration policy: retain each run's evidence and artifact; distinguish harness defects, model/artifact defects and controller mistakes.
