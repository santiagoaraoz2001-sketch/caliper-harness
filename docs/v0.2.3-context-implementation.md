All production compaction owners are wired to the configured client's preflight: normal run, launched worker, and manual TUI compaction. Injected test judges may omit preflight because they do not necessarily have a transport ceiling. Native/chat preflight does not pretend to know the remote tokenizer limit; provider admission remains authoritative.

The summary reserve is planning headroom, not a strict output limit or token estimate. Oversized actual summaries are refused intact. Required user/current facts that cannot fit still produce an explicit failure before generation; they are never truncated to make the test pass. The candidate cache belongs to the current Runner and does not survive process/Runner recreation. Persistent candidate recovery would require a separate lifecycle contract and has not been claimed.

## Remaining judgment roles

| Role | Why retained / narrowed | Unavailable / low-confidence behavior |
|---|---|---|
| PAT/product advice | Narrow successful mechanical steps; retain new steering, current errors and finals. | Transport/timeouts are recorded as unavailable advice and work continues; low confidence adds no instruction. Encoding, durable recording and cancellation remain authoritative failures. |
| Discovery/progress advice | Existing cadence, phase changes, repeated failures and unfinished-response boundary. Recorded benchmark proves serial cost, not counterfactual benefit. | Unavailable/invalid/low-confidence verdicts add no guidance; no duplicate same-phase retry caused solely by outage. |
| Thinking-loop advice | Existing repeated-thought detector; does not replace current execution authority. | Optional samples can be reduced for provider admission; unavailable/invalid verdicts continue without invented advice. |
| Readiness/coherence | Required existing launch/claim contract; not equivalent to progress advice. | Unavailable refuses admission; low confidence asks for explicit human admission. |
| Tool authorization | Existing risk policy and approval owner. | Unavailable blocks the action; low confidence asks the user. No change to these semantics. |
| Compaction factual admission | Original context cannot be replaced without its existing factual admission or explicit disabled-mode manual approval. | Capacity now fails early; failed judgment retains context and candidate; rejection/low confidence retains context. |
| Style send-back | Existing optional once-per-run advice, not visual proof. | Unavailable/low-confidence/invalid verdicts do not block validated handoff. Graph design identity/application work is tracked separately. |

## Guiding-principle checks and open scope

No new user-facing tool, config switch, prompt catalogue, review layer or model obligation. Existing host-owned state supplies scheduling, byte admission and provenance. Dry reduction is logarithmic in optional history count; candidate retention is one proposal. Current authority and observations are never synthesized from a verdict. The graph/PAT owner contracts and manual authorization remain intact.

PERF-006 repeated prefill still requires adjacent exact request-prefix/cache/slot evidence before changing provider cache behavior. This change does not establish a prefill root cause or optimize an unmeasured cache. CONFIG-001 role assignment/configuration and end-to-end optional-advice comparison remain in the overall release map. A true native-model usefulness comparison is a later authorized validation phase, not accomplished by deterministic unit tests or by disabling every judge role.
