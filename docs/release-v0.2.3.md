# v0.2.3

This release adds navigable domain guidance, test-suite management and harness-owned native continuation, with repairs to planning, durable feedback and verification. Release publication is gated on the exact source/build checks and complete platform asset inventory. The benchmark is stopped; a new benchmark is not part of this release operation.

## Behavior changes

- Windows terminal paste preserves Unicode and multiline input as one submission through the real console boundary. Ask choices use one option per line so natural commas remain part of a label. `/btw` preserves authored spacing.
- PAT exposes the current field instead of a broad future-field schema, rejects unsupported authored fields instead of silently dropping them, and reopens the same task for counterevidence. An unchanged stopped task can be requeued without rewriting its brief; the new attempt still requires fresh checks.
- User feedback has distinct captured and committed events. Late feedback can be saved against its exact task/attempt without granting execution authority. Capture failures preserve the popped intent in memory.
- Independent acceptance and project checks both run and retain separate outcomes. A passing project suite cannot erase failed acceptance. Check cannot inherit persistent-service actions.
- Well-correlated native arrays with duplicate argument keys are refused before effects and can be corrected on the next call; raw authored evidence is retained.
- Compaction checks the actual decision-service request limit before summary generation, bounds older retained evidence in the judgment projection, and retains an unchanged candidate within the same Runner for retry. Historical comments no longer force repeated judgments after every successful step.
- Guided coding receives the same concise graph-use instruction as other coding roles. Existing searchable standards now cover relevant design preference elicitation/reuse, purposeful handcrafted UI/motion, state ownership and meaningful code-quality evidence. Full guides remain on demand.
- Existing Bash supports a session-owned service lifetime when an owner exists, with bounded TEMP diagnostics and exact owned-tree cleanup. Ordinary commands and checks remain bounded. Runtime discovery verifies Windows Store Python aliases; lifecycle errors no longer masquerade as missing-shell errors.
- Update paths report phase, transfer bytes, elapsed time and verification progress. Extraction and verification honor cancellation; TUI progress uses one row. Immutable preparation remains separate from activation.

## Domain knowledge and tests

- Design, testing and code guidance use compact entry sections, linked topic explanations and worked deep dives. Examples include design-language decisions, asset alternatives, independent collision oracles, save/upgrade round trips and duplicate-effect accounting. User- and agent-authored graphs use the same section/reference navigation.
- Domain articles start near 1,000 tokens and have a 2,000-token retrieval budget, including preferences and navigation. Ordinary project identity, testing strategy, PAT state and task facts do not inherit this domain budget. Exact model counting and conservative unsupported-provider admission are distinguished explicitly; see [domain guidance](domain-guidance.md).
- Planning may pin returned knowledge sections to immutable versions. The selected body reaches subsequent planning and admitted worker/reviewer requests; deeper linked bodies remain lazy. Selection does not grant execution or write authority.
- `/tests` manages optional suites, selected specifications and guidance. Test design starts with a reviewable unsent draft. Failed and cancelled runs retain distinct evidence, and model-facing evidence supports paging beyond the first result page.
- Required report contracts can declare per-stage prerequisites and expected evidence. Missing stages, required skips, missing observations, stale run IDs and failed public consumers cannot qualify. Host prerequisite checks and producer-reported observations remain distinct; artifact references alone are not proof.

## Planning, recovery and prompt cost

- Planning respects the requested stopping point: drafting-only leaves drafts; readiness-only does not claim or ask to execute. Build/fix requests authorize the normal readiness/claim sequence.

- Rulith output-limit continuation resumes the exact rendered prompt and raw response prefix through its existing native endpoint. Partial tool frames do not execute; effects commit only after a complete validated call. No recovery user prompt or server modification is inserted.
- Planning publishes the current host-owned question and authenticates correlated receipts before omitting duplicate schema text. Current project knowledge updates replace one scoped frame at a complete-response boundary.
- Readiness includes the Approach's declared scope and collective Task coverage. Approval remains bound to the exact displayed owner and brief; a scaffold-only task does not prove a broader product scope.
- Repeated draft supervision and duplicate reviewer attachments are reduced while current checks, failures, source evidence and original human intent remain available. Prompt examples consistently discover headings before requesting one domain section.

## Compatibility and limits

The current-question PAT process and GraphQL/Kuzu foundation remain. No additional runtime review layer or reusable workflow/block builder is introduced. Updates preserve project work, settings, graph data, sessions and prior application versions.

Model uptake, aesthetic quality, arbitrary generated-code correctness, comparative Judge usefulness and provider cache benefit remain measured outcomes, not guarantees inferred from these changes. The runtime-size target below 20,000 lines remains open; simplification is a separate parked workstream. Platform builds, installer preservation, native checks and npm package integrity have separate release evidence; skipped or unavailable checks are not passes.
