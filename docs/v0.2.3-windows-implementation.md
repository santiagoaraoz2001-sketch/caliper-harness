## Burden and lifecycle constraints

- No new tool, agent, judge pass or review layer. Only explicitly owned Bash definitions add one optional `service` enum. Ordinary Bash remains unchanged. Service mode refuses `timeout` instead of silently ignoring it; ordinary executor still supplies its configured timeout.
- A service has one mutex-protected owner, one process tree and one TEMP log. Output is drained while only the first 4 MiB is persisted. The existing serve owner closes the writer on settlement; output-pipe waits remain bounded. No persistent startup registration is created.
- `service=status` includes up to 2 KiB from the end of that retained prefix, explicitly labeled retained/capped rather than a complete or current log. Only status includes diagnostics; start receipts stay small. The reader uses the owner-created path, checks original file identity, and performs bounded seek/read; replaced files and symlinks cannot become arbitrary TEMP reads. A real failing foreground service fixture proves stderr remains available after exit, output is bounded, and substituted file content is refused.
- Observer raw logs/receipts and fixture evidence remain in TEMP. Persisted documentation contains paths and conclusions, not copied trace dumps. UI-action evidence remains sent/unverified until separately observed; host done never means output quality passed.
- Tool registration does no runtime subprocess probing. Alias validation occurs only when selecting/checking the executable; normal paths retain `LookPath` behavior.
- Windows input adapter is a small local compatibility module, not a second terminal framework. Existing Bubble Tea parsing and the product textarea still own key semantics. A Windows-only size ticker emits only on actual changes and is cancelled at program exit.
