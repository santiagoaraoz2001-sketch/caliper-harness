## What the model did well, and what was underdeveloped

The DOM-free simulation, seeded world generation, fixed timestep, explicit pricing/perk functions and meaningful negative tests are useful foundations. The model also performed a valuable negative-control test of the pause-overlay repair: E:97 at 21:36:16 records four browser failures when the defect was reintroduced, then a passing repaired run. Keep these practices.

The pattern is uneven integration, not proof that the model was globally rushed. It spent substantial time on planning and physics probes, while persistence, entry points, UI/domain boundaries and long-lived event behavior received narrower verification. Calling those areas hurriedly integrated is supported by the incomplete contracts and their chronology; attributing impatience, time pressure or a specific hidden reasoning cause is not.

Large files alone are not defects. The current roughly 1,600-line simulation and 1,166-line browser shell matter because ownership crosses them inconsistently: simulation helpers rely on callers for important rules, the browser directly mutates domain state, and persistence and UI transitions have their own partial versions of those rules. Splitting files by an arbitrary size limit would not fix that.

## CODE-001 — Partial save restore passes the advertised reload test

**Evidence:** [main.js](../../benchmarks/space-transporter-v022-r1b/src/main.js), imports and lines 622–666; [browser.test.mjs](../../benchmarks/space-transporter-v022-r1b/test/browser.test.mjs), lines 280–289. C:584 at 20:51:27 contains the loader write; C:469 at 20:48:05 contains the credit-only reload assertion. E:80 at 21:35:39 and E:97 later report that assertion passing.

**Confirmed source/probe result:** `loadGame` changes credits, XP and other fields, calls `recomputeShip` without importing it, catches the resulting failure and returns false. The caller stores that return in unused `restored`. An isolated save/load probe restored credits to 1234 but returned false, reset position to the new-game start, lost the active contract and reset cargo/fuel. The existing browser assertion compares only credits, so its condition still passes. The caught error does not appear as an uncaught browser console error.

**Why it survived:** the test proves one field, while its name and notes claim progress restoration. Broad error swallowing and partial mutation hide the failed transaction. Syntax checks cannot detect this missing binding. The harness accepts the declared check's actual exit status; it cannot infer full semantic coverage from that status.

**v0.2.3 repair:** use the existing task acceptance and on-demand code guidance to connect persistence promises to meaningful roundtrip state and failure behavior. Existing graph architecture entries should identify the persistence owner and relevant state. Validate/decode before committing live state; expose failed persistence rather than leave unexplained partial success. Do not add an always-on JS linter or universal serializer to Caliper.

**Acceptance:** a small fixture with this missing binding/partial commit cannot satisfy a full-restore claim; the narrow credit-only test is described narrowly. Verify active work, location and resource state as applicable, plus corrupt/denied storage. Harness-side tests ensure failed/unverified evidence is not promoted to completion. Future model uptake remains to be measured.

## CODE-002 — Save projection omits the state that gives values their meaning

**Evidence:** same loader and `saveGame` lines 595–619; simulation contract deadlines use `world.time` and cargo load in [sim.js](../../benchmarks/space-transporter-v022-r1b/src/sim.js). Same C:584 write.

**Confirmed, separate from CODE-001:** supplying only the missing import binding in an isolated VM lets the unmodified loader return true, but a saved active trip with cargo 42, fuel 15 and world time 120 returns with cargo 100, fuel 120 and time 0. Cargo load is absent. Absolute contract deadlines are retained without the corresponding clock. This is a counterfactual isolation probe, not a claim that the current broken loader successfully restores contracts.

**Cause/impact:** persistence was treated as a list of convenient fields rather than a defined snapshot of authoritative state and explicit reset policy. The code can change economic/deadline behavior even after the obvious import bug is fixed.

**v0.2.3 repair/acceptance:** reuse the code standard's state/persistence section and capability-to-evidence links. Specify what survives, resets or migrates; test the promised invariant across save/load and failure. No automatic exhaustive object inventory. A bounded fixture must detect a lost elapsed clock/resource balance, and intentional reset semantics must be reflected in user copy and tests.

## CODE-003 — Domain guarantees live partly in caller convention

**Evidence:** `sim.js:1182` acceptance, `:1217` docking check, `:1256` payout; `main.js:807` `renderBoard(origin)` does not use its origin argument to filter offers. A:952 at 16:40:38 authored the simulation functions.

**Confirmed direct-domain probes:** acceptance permits a contract whose origin differs from the current starting station; accepting a second offer leaves two contracts with `state=active` while replacing the active ID. Calling payout on an available, unaccepted contract succeeds and adds 1604 credits in the fixture. The visible docking handler normally calls a check before payout, so this is not evidence that every payout bypass is currently accessible through ordinary UI.

**Cause:** critical preconditions are not owned by one explicit domain operation; positive-path callers supply implicit protection. The graph does not currently give the model a used, authoritative map of which layer owns each invariant. Repeated helper tests can preserve the same mistaken calling assumptions.

**v0.2.3 repair:** concise architecture guidance and linked capability entries should name the owner of an invariant, actual callers and required preconditions. Prefer one existing domain path enforcing the rule over duplicating checks in unrelated handlers. An internal helper can have a narrower contract if it is clearly internal; do not demand defensive validation at every function.

**Acceptance:** fixture operations demonstrate rejection of invalid sequencing or an explicitly constrained internal API; ordinary entry-path tests include repeat acceptance, wrong location and payout eligibility. These fixtures test general state ownership, not hardcoded trucking mechanics in the harness.

## CODE-004 — Restart is an independent state-mutation path with inconsistent accounting

**Evidence:** `main.js:919–932`, DESIGN recovery policy; A:2429 at 17:22:30 first browser-shell write, C:696 at 20:58:48 later persistence-related edit.

**Confirmed probe:** restarting changes hull 20→100 and cargo 30→100 while retaining the same contract and 320 credits. The design says recovery always costs something; restart is also a visible advertised control. Whether this should be a rollback, abandonment or paid recovery is a product-policy decision, not something the audit should invent.

**Why missed:** verification emphasized ordinary tow and payout while reset/restart mutated overlapping state through a separate browser handler. Design prose was not reconciled with all entry paths.

**v0.2.3 repair/acceptance:** capability/architecture links and existing verify guidance cover alternative entry paths for the changed state: restart, cancel, retry, reload and recovery. Make the intended policy explicit and test it. Share the owning transition when appropriate instead of adding a new enforcement framework.

## CODE-005 — A bounded buffer and an unbounded logical cursor disagree

**Evidence:** `sim.js:1053–1057` appends events and shifts the array above 240; `main.js:945–959` consumes using `evIndex < events.length`. Producer trace A:952; consumer trace A:2429.

**Confirmed exact-function probe:** consume 240 events; append event ID 241 through the original producer; buffer stays length 240, consumer notices stay 240. The index has reached the maximum array length and no subsequent appended event is consumed. Impact/disabled feedback can consequently disappear in a longer session. This was not established through prolonged live gameplay.

**Cause:** producer retention and consumer position were designed separately. A short happy-path run never reaches the trim boundary. The event already has a monotonic ID, but the consumer does not use it.

**v0.2.3 repair/acceptance:** add a brief bounded-stream/cursor example to relevant code guidance and use it in existing developer fixtures. The smallest application-level correction is a coherent sequence/consumption contract using existing IDs or owned draining, not another event-bus library. Test before/at/after retention rollover and repeat consumption. Apply the same principle to Caliper's controller/session cursors where relevant; do not assert an identical undiscovered harness bug.

## CODE-006 — Repairing false positives introduced false negatives in the verifier

**Evidence:** [inspect.mjs](../../benchmarks/space-transporter-v022-r1b/scripts/inspect.mjs) blanks strings/templates; [check.mjs](../../benchmarks/space-transporter-v022-r1b/scripts/check.mjs) applies it to HTML/CSS before URL tests and to JS before global-use tests. C:429–457 at 20:45:56–20:46:41 contains this repair sequence, related to QA-004.

**Confirmed negative controls:** raw `<script src="https://example.invalid/app.js">` matches the external-resource rule; after `codeSkeleton` it no longer matches. Executable `window.location.href` inside a template interpolation is also erased. The repair stops some false positives but defeats parts of the promised check.

**Cause:** a generic handwritten scanner was reused across different language contexts. The fix was checked against formerly rejected good code, without equivalent prohibited examples proving the detector remained useful. More custom analysis code increased the maintenance burden.

**v0.2.3 repair/acceptance:** existing verification guidance distinguishes safe-example fixes from meaningful negative controls. Remove redundant/unsupported checks or use a narrow language-appropriate inspection for an actual requirement. Avoid a new general parser/audit dependency. A checker repair must retain detection of the forbidden case and acceptance of the allowed case; label limits instead of claiming completeness.

## CODE-009 — Hot-path work deserves measurement, not an assumed optimization

**Evidence:** `main.js:989–1089` rebuilds log HTML and updates many DOM nodes every frame; station drawing and navigation repeatedly call `getComputedStyle`; station docking facts are recomputed in drawing, HUD and prompt paths. A:2429 authored these paths.

**Status:** source-confirmed repeated work, unmeasured performance impact. No new FPS, leak or responsiveness failure is claimed. A small scene may still run adequately.

**v0.2.3 opportunity:** the existing performance/code guidance should favor observing the actual hot path and reusing stable DOM references/style/state calculations only if measurement warrants it. Frame timing, mutation counts and allocations are better evidence than a rule that forbids all per-frame DOM writes. No blanket caching, component framework or background instrumentation feature.

**Acceptance:** bounded profiling separates render/simulation/DOM costs at the intended workload; any optimization preserves behavior and shows a measured benefit. This is an open measurement opportunity, not a confirmed defect requiring speculative code.

## What Caliper itself must change

The generated defects do not mean the host should implement a universal code reviewer. The cross-check supports existing, concrete host repairs:

- `internal/tool/normalize.go:77` drops current-call fields considered stale planning vocabulary: replace silent loss with a coherent current-step contract (PAT-004).
- `internal/agent/agent.go:644` logs feedback before `CommentAppend` succeeds, and assigned ownership can reject it: fix persistence/ownership and committed acknowledgements (RUN-001).
- `internal/agent/compact.go:296–358` judges after summary generation and serializes all retained protected anchors/call IDs: bound/preflight the actual decision input and preserve safe recovery (D1-003).
- `internal/tools/process/process_windows.go:36–75` kills descendants when an ordinary call's job closes: provide the correct existing owned persistent-service lifetime rather than pushing the model toward startup/scheduler workarounds (WIN-010, SCOPE-001).
- Existing verification can accept a successful declared command whose assertions are narrower than its prose. Fix truthful host evidence handling, phase-consistent graph/help and meaningful task acceptance; use targeted developer fixtures to test these causal paths. Do not pretend the host can automatically prove arbitrary program semantics.

## Execution implications

CODE-001 through CODE-008 are confirmed source/probe findings with the qualification limits above; CODE-009 is a measured-work opportunity still awaiting measurement. Each is recorded in the same append-only ledger and mapped to execution work. Repairs primarily strengthen existing state, evidence, scope, graph and instruction contracts. No universal review pass, mandatory lint stack or extra judge is proposed.

Closure has two parts: prove deterministic harness changes with regressions, and separately observe whether the model now uses the improved contracts to produce stronger code. A better guide alone cannot close an empirical model-quality claim. Existing benchmark artifacts remain unchanged as evidence.
