# v0.2.3 post-audit lifecycle repairs

This records local implementation and controlled regression evidence. It does not claim a released build or a successful new live model qualification. The complete issue inventory remains in the execution plan, post-audit changelist, failure map and append-only failure ledger. v0.3.0 work is excluded.

## Scope and ownership

Owned changes cover agent execution/finalization, run factories, launch/worker/reviewer lifecycle, plan feedback/presentation, session provenance and the existing authorization receipt owner. Prompt text belongs to the parent integration; context/compaction and graph evidence projection belong to the context agent; TUI queue transport and display belong to the Windows agent.

### SCOPE-002/003 and PAT-010/015: observation is not execution

Ordinary factory runs now acquire a coding verification obligation only from an actual filesystem publication/observed shell effect, an explicit check, or an actual task claim. Selecting or inspecting historical unfinished work does not adopt its execution obligation. `workflow_status` returns a successful observation even if the observed work is not qualified; it does not register an execution obligation. Actual launch/resume invocations and actual claims retain their qualification rules.

This removes host-triggered implementation/check pressure from plan-only and reporting turns. It is not a semantic classifier capable of enforcing arbitrary natural-language restrictions before every proposed effect. Existing authorization and task admission gates remain in place. No prose keyword classifier or new user mode was added. Conditional context instructions use the same current-obligation predicate.

Regressions: `TestInspectionDoesNotAdoptHistoricalCodingObligation`, `TestProjectEffectActivatesCodingButNoEffectDoesNot`, `TestOutcomeActualWorkflowRefusalReachesParent`, existing optional-planning/settled-task closure tests. Tests explicitly distinguish successful request completion from qualified project work.

### WORKER-001, VERIFY-001/003/005 and PROMPT-002: one real paired check contract

Actual owning dispatched workers now receive the registered native `check`, the frozen task/attempt commands, and the same CodingExec receipt owner as direct execution. The live worker receipt passes to settlement; a separate host fallback does not rerun a current pair. This does not reuse stale archived checks or qualify a task from ordinary Bash output. Failed/interrupted worker episodes are retained too.

Check stages use the existing configured shell maximum as their default timeout; ordinary Bash keeps its existing shorter default, and an explicit shorter timeout is honored. Acceptance and project suite execute independently except after cancellation or receipt-persistence failure. Both successful complete receipts remain required. Canonical help/purpose is corrected to match that behavior.

Red/green reproduction: `TestChildHelpSeesLateAssignedCheck` first failed on every actual structured worker request because `check` was absent; after repair it exposes check, runs the actual worker pair and independent reviewer pair, and counts no extra host suite. `TestCheckUsesVerificationCapBothStagesAndHonorsShorterRequest` checks both stage arguments, current receipts and unchanged ordinary Bash defaults. The existing paired-stage negative controls remain required.

Limit: an exit-zero script that skips its own assertions still proves only a settled exit, not behavioral coverage. Receipts explicitly say coverage is unknown. No generic `SKIP` string classifier was introduced. Missing-dependency negative controls and meaningful project test contracts must establish coverage; QA-005/CODE-007 are not declared universally solved by prompt text.

### REVIEW-001/002: bounded independent review

The actual reviewer registry exposes existing read/search/read-only knowledge operations and the frozen task-bound `check`; it omits free-form Bash, write and edit. Arbitrary reviewer shell probes and scratch writes are therefore refused before effects. The proposed scratch-directory mechanism was removed because it is unnecessary under this smaller authority surface. No OS sandbox, new tool or review tier was added.

`TestReviewerShellMutationCannotQualify` now covers three concrete paths: free-form Bash refused with source unchanged, a substituted `check` command refused with source unchanged, and the authorized frozen check script itself modifying source. The last path invalidates the review and stops before another model request; cleanup cannot turn it back into a pass. Parent cancellation remains distinguishable from role failure. `TestChildHelpSeesLateAssignedCheck` inspects actual structured requests: worker Bash remains available, reviewer Bash is absent, and reviewer native check/help still execute the exact pair.

Limit: the frozen authorized project check may itself write files. That existing contract is observed after effects and invalidated if it changes project content; this is not an OS filesystem sandbox. Missing additional reproduction evidence must be reported as UNVERIFIED instead of inventing another command. Unsupported reviewer conclusions still need explicit source/receipt provenance and controlled reviewer qualification; self-review cannot count as independent review.

### PAT-009/013/014 and CLI-001: feedback and readiness are usable and auditable

The existing user-feedback append accepts attempt-zero feedback only for a never-started queued task in a draft approach under an open plan. It does not confer execution or delivery authority; running model-authored comments retain their stricter claim gate. TUI routing/toasts use the user-feedback owner.

Structured goal/sketch values render as readable fields for human readiness, including unknown nested fields and exact numbers. Stored contracts and snapshot hashes remain unchanged; terminal control characters are made literal. Manual readiness approval, denial and cancellation use the existing owning approval sink with approach ID, exact snapshot, original raw brief, workspace/store/session and decision. Persistence failure cannot look approved. Both disabled-judge readiness and uncertain-verdict human decisions use this path.

Regressions: `TestDraftFeedbackDoesNotRequireOrGrantExecution`, `TestDisplayStructuredRetainsAllFieldsWithoutJSONEscapes`, `TestReadinessDecisionRecordedBeforeReturn`, and the actual public factory/real Store `TestPublicManualReadinessDenialHasOwningDurableReceipt`. The unbound-plan refusal now names the existing explicit `bindPlanProject` route without suggesting cross-project rebinding.

### RUN-001 and RESUME-001: one durable message across the active role

An assigned main runner is synchronously blocked while its independent reviewer runs. That reviewer now becomes the sole consumer of the existing parent feedback queue and generation interrupt, preserving exact task/attempt ownership. Fan-out workers do not receive another task's queue. Capture, owning persistence, and later model uptake remain distinct events.

The queue uses exact `UserNote` envelopes with stable ID and original session. TUI persists `btw_queued` to the existing session archive before enqueue; failure refuses submission visibly. The Runner snapshots pending notes before acknowledgement. `btw_ack` is written to the original archive only after durable placement. Restore reconciles queue/ack identities even when queue events precede the latest continuation. Conflicting identities fail; repeated acknowledgement does not duplicate intent. User task feedback uses the same stable ID for idempotent append within the exact task/attempt. No second queue store or new tool is added.

Regressions: `TestDurableNoteAckFailureRetainsExactPendingThenRetriesOnce`, `TestQueuedUserNoteSurvivesSnapshotAndAckIsIdempotent`, `TestActiveReviewerConsumesOwnedFeedbackAndAcknowledgesOnce`, plus TUI enqueue-failure/restoration controls. Exactly-once here describes owning note placement; it does not claim a model never rereads context after an interrupted generation.

### CTX-001: consumed human answers remain constraints

Text Ask answers carry protected `answer` provenance. Native Ask results preserve their correlated call/result group after consumption. Protection survives snapshot/restore; it is not dependent on the answer still being unread. `TestConsumedAskAnswerProtectsEntireNativeGroup` and existing exact-byte Ask fidelity checks cover this without copying a whole guide into context.

### GRAPH-010: stop rewriting the whole role log on every event

Raw worker/check/reviewer events append to the existing session JSONL archive. The owning task log stores one immutable session reference per phase, then final outcome/receipt metadata. Each archive starts with workspace and exact task/attempt/phase owner provenance. Each event still checks the actual owner. Old inline event arrays remain readable; finalization preserves new refs and concurrent comment records. Source/graph integration streams selected evidence with exact role-owner checks, including archived task worktrees, without opening a second store.

`TestRoleArchiveDoesNotRewriteGrowingGraphLog` compares actual graph bytes before/after twenty growing role events, verifies all archive events survive, and checks idempotent/conflicting user feedback. Graph integration adds wrong-owner and bounded selected-page controls. Native transaction/checkpoint synchronization is owned by the context/store agent. The audit proved whole-log write amplification; it did not prove that amplification alone caused the native checkpoint error.

### Final-suite RESUME-001 regression and correction

The correction removes metadata-only exposure inference from the factory and all TUI paths (Update, View, run completion, helper and labels). The existing ToolView field records an explicit coding/full/workflow choice, not the projected role registry. Workflow exposure requires scope. An explicit `/workflow` resolves the existing live store/node and validates captured project ownership, then writes its choice and scope together in the existing continuation before changing the UI. A failed persistence or foreign owner leaves both untouched. `/tools coding/full` clears selected scope as before but preserves Assignment and Coding metadata exactly; subsequent live admission still owns any actual claim/check authority. Model-selected nodes do not create an explicit workflow preference. Historical empty metadata remains coding with its selected node retained; it never guesses broader exposure. No new field, tool, schema family or review layer was added.

The final distinguishing controls include actual resumed structured requests for legacy/default plus selected scope, saved/explicit coding, saved/explicit full, saved/explicit workflow, explicit coding overriding saved workflow, and invalid workflow-without-scope. Foreign store/project restoration fails before a model request.
