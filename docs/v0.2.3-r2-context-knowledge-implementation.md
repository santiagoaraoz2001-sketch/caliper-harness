## Principles and tradeoffs

- No dependency, model-facing tool, judge, review tier or model checklist was added. Graph help is derived from the existing executable schema. Recall became shorter in implementation and retains the same output budget.
- Host code owns call correlation, projection admission, current-error eligibility, archival references, reader/write settlement and honest provenance. It does not guess a design identity or manufacture an execution result.
- Successful read-only receipts avoid per-call judging. The ordinary cadence watcher and existing authorization/readiness/final verification owners remain separate. Controlled call counts demonstrate avoided work; they are not a cross-release speed comparison.
- Compaction retries are limited to typed pre-inference capacity refusals. Projection removes optional historical material in batches with hashes/omission disclosure; source/context remains intact and the summary is not regenerated. If mandatory content cannot fit, the operation reports failure rather than silently losing it.
- Reader exclusion serializes native writes against concurrent readers. This trades some read/write overlap for safe checkpoint settlement. Admitted cancellation waits for native ownership to settle; the RWMutex itself has no cancellation API. Context is rechecked and the native timeout recomputed immediately before execution. Transaction callbacks must use `Tx`, never outer `Store` reads/writes.
- Model-level claims remain distinct from empirical proof. A component test passing does not prove future aesthetic quality, factual summary completeness, useful judge decisions, arbitrary natural-language negation, or improved end-to-end benchmark speed.
