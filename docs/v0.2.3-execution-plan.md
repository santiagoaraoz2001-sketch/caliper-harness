# v0.2.3 execution plan

Prepared 2026-10-24. Implements the full [scope map](v0.2.3-scope-map.md), including the [code/trace audit](v0.2.3-code-trace-audit.md). Work order follows dependencies; it is not a selection of priorities or permission to omit later items. Implementation with subagents is now authorized and in progress. The prior benchmark and automation remain stopped; publication and a new model benchmark are separate from this build.

## Intended result

A smaller, more dependable harness: exact input; coherent PAT transitions; recoverable execution and user steering; bounded context/judge work; useful graph retrieval; stronger code/design outcomes; truthful qualification; Windows lifecycle/update reliability; and evidence for every advertised existing feature.

Every issue retains its original evidence, causal classification and current state. The complete scope includes all earlier local/released repairs, all separate-document findings, all 19 Luna records and CODE-001–009. Expected protections and withdrawn allegations stay documented as such. Historical artifacts are not edited to manufacture a better benchmark result.

## Implementation rules derived from the eleven principles

| Principle | Concrete constraint on execution |
| --- | --- |
| Simplicity/lightness; bloat is a defect | For each change, name what existing code/instruction/work it replaces or removes. Prefer a small correction to an existing owner. No new review tier, agent, universal audit engine, workflow builder or speculative subsystem. |
| Offload work; host-owned mechanics | Host computes IDs, scope, legal transitions, request budgets, receipt freshness and process ownership. The model should supply the current substantive answer, not repeat protocol state. |
| Structured steps | Keep field-at-a-time PAT and concise exact next actions. Do not replace it with a giant all-fields schema or free-form procedure that small models must memorize. |
| GraphQL/Kuzu foundation | Use the existing knowledge/version/reference surface for relevant identity, capabilities, architecture and code anchors. Update meaningful changes, not every edit or symbol. |
| Consistency | One canonical rule feeds active role prompts, schema/help, validation and recovery. Inspect actual assembled requests; testing a disconnected string is insufficient. |
| Small tools; useful help | Few required arguments, concrete schema-valid examples, current availability and exact recovery. Advanced material is retrieved on demand. |
| Evidence over claims | Separate planned/implemented/verified and pass/fail/skipped/missing/stale. A local fix, a component test and a successful observed model run are different evidence. |
| Total burden | Track request bytes/tokens, calls, wall/active time, memory, repeated prefill and recovery effort. Reject simplifications that merely shift work or errors to the model. |

The UI standard remains at most 2,000 tokens and stays on demand. The existing code standard remains concise and topical; add the new audit lessons by replacing/clarifying relevant text, not appending nine compulsory checks. No arbitrary line-length/module-size caps. No blanket dependency ban: distinguish product runtime dependencies from legitimate development tooling.

See the [per-issue implementation and acceptance index](v0.2.3-implementation-coverage.md) for the original 90 main findings and 19 earlier Luna records. These are historical inventory counts, not the current total; the ongoing v0.2.3 [failure map](v0.2.3-failure-map.md), [ledger](../../test-findings/failure-ledger.jsonl) and [feature matrix](../../test-findings/v023-user-feature-coverage.md) add current failures and qualification limits without closing earlier issues automatically.

## Work packages and dependencies

Every work package must carry seven developer-side acceptance records, using existing tests and this plan rather than new model-facing review layers:

1. **Contract:** link each failure/opportunity to the responsible owner, observable before/after behavior and a distinguishing acceptance condition. Record confirmed causes separately from hypotheses.
2. **Simplicity:** state what existing work, code or ambiguity the repair removes. Explain any new branch, dependency, stored state or instruction; reject speculative additions and duplicated owners.
3. **Causal proof:** demonstrate a reproducer failing for the recorded defect and passing after repair where practicable. Preserve negative controls. Missing pre-change proof stays explicit.
4. **Faithfulness:** inspect the actual assembled role request, native schema, help, validator and recovery result together. Preserve field-at-a-time PAT, concise relevant graph retrieval, and consistent authority boundaries.
5. **Total burden:** record comparable request bytes/tokens, tool/judge calls, latency, memory and recovery effort where affected. Do not claim a reduction from prompt length alone. UI guidance must remain at most 2,000 tokens and on demand.
6. **Real boundaries:** test relevant Windows PTY, filesystem, process, persistence, package and public command paths. Controlled fixtures prove mechanics; they do not establish spontaneous model uptake or product design quality.
7. **Closure:** retain a row for every issue, including historical repairs and verified non-defects, with implementation state, evidence and remaining qualification. Full local checks precede any candidate claim; empirical benchmark and publication states remain separate.

The primary agent integrates disjoint subagent changes and reviews the combined behavior. A green component test cannot close unrelated findings or substitute for the existing feature coverage matrix. No issue disappears because another repair has greater priority.

### E01 — Repair the observer before relying on it for qualification

**Dependencies:** E00. **Scope:** category 11; CTRL-002–006, TEST-001/003/004/005.

**Existing owners:** `scripts/run-observed-benchmark.py`, `scripts/test-observed-benchmark.py`, observer documentation and the coverage matrix.

- Use bounded trustworthy screen/complete redraw state; do not infer UI selection from concatenated ANSI-stripped history. Route input according to actual modal/view/composer and submit once.

**Acceptance:** fixtures exercise more than 50 mixed UI actions, native asks, stale/worker sessions, interruption without old host outcome, all terminal states and captured-but-uncommitted feedback. Existing controller tests remain meaningful. Real PTY qualification follows E02; no model needed for these fixtures.

**Burden removed:** blocked audits, duplicated inputs, false attribution and noisy redraw analysis; no production feature added.

## What completion means

### Implementation checkpoint

The build and evidence are tracked in [integration validation](v0.2.3-integration-validation.md), with all individual issues retained in the [coverage index](v0.2.3-implementation-coverage.md). This checkpoint separates code delivered from empirical release qualification:

| Package | Implemented / retained | Qualification still distinct |
| --- | --- | --- |
| E00 | Original evidence preserved; 90 main IDs, 19 Luna records, new E09-INPUT-003 reconciled | No historical result silently upgraded |
| E01 | Exact session adoption, bounded controller state and captured/committed delivery distinctions | Every live UI subflow still needs its own evidence |
| E02 | Real Windows input boundary, unambiguous ask choices, current-field PAT, recoverable correlated duplicate arguments | Corrupt uncorrelatable calls remain refused; native-model behavior is not a fixture result |
| E03 | Same-task counterevidence revision, unchanged-brief requeue, late feedback persistence | New attempts require fresh checks; unsafe cross-attempt reuse is deliberately excluded |
| E04 | Exact judge preflight, bounded history projection, unchanged candidate reuse within a Runner, comment novelty | Provider prefill and comparative judge usefulness require measurement; no cross-process candidate persistence claim |
| E05 | Owned service lifetime/diagnostics, verified runtime selection, accurate process errors, UTF-8 boundary; prior path/startup repairs retained | Actual platform evidence is enumerated, not generalized to every OS |
| E06 | Guided-role graph instruction repaired; existing sections/references/anchors and role boundaries retained | Spontaneous graph retrieval/application needs model observation |
| E07 | Preference elicitation/reuse and handcrafted identity guidance within existing standard | Better output aesthetics are not proven by changing prose |
| E08 | Independent check results, preserved failed acceptance, source-owner/state/evidence guidance | Generated-code quality and meaningful arbitrary assertions cannot be certified by the host alone |
| E09 | All 33 commands and advertised subflows mapped; `/btw` whitespace and concrete integration faults repaired | Untested live subflows remain visible in the feature audit |
| E10 | Progress/cancellation, immutable staging, package version metadata, local build and controlled installer tests | Real migration/rollback, active-version-aware cleanup and publication belong to the deployment qualification phase; no installed version is deleted during this build |
| E11 | Combined regression and developer evidence report | Next user-authorized native benchmark, comparative burden and supported-platform release checks remain separate |

The inventory drives closure, not a chosen subset of impressive fixes. Each item ends as: repaired and regression-verified; earlier fix retained/requalified; confirmed expected behavior/withdrawn allegation; or explicitly unresolved with evidence and its release consequence. Do not close model-uptake or output-quality failures solely because instructions were edited. Do not claim every possible future model mistake can be eliminated.

Keep v0.3.0's reusable workflow builder, block authoring, machine-wide workflow library and custom tool enable/disable product out of this release. Apply their underlying reliability lessons through the existing mechanisms described here. Implementation is authorized; restarting the stopped benchmark is a separate phase.
