## Receipt reuse policy, explicitly resolved

Do not relabel an earlier attempt's check as a fresh check. Inspection found that `session.CheckReceipt` has task-associated revision/command/cwd metadata but no persisted checked-source fingerprint. `Runner.WorkspaceFingerprint` currently measures persistent project changes around Bash, excludes ignored Git files, and explicitly does not attest external or temporary effects. Run entry resets Assigned authority; `task_start` claims a new attempt and constructs a new CodingState.

These existing records cannot prove “same source and same authorized attempt” after terminal interruption. The small safe repair removes unnecessary brief rewriting and Ready transitions, while preserving history and requiring fresh checks after a new claim. Existing current receipts within the same live admitted attempt remain usable. Cross-attempt reuse is deliberately not implemented; absence of a trusted freshness proof is a refusal, not missing evidence to fill with model claims. A future implementation would require an actual source/effect boundary and persistent ownership attestation, not copying a receipt or weakening attempt checks.
