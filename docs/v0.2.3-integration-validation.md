## Root integration repairs

**GRAPH-003:** guided planning omitted `system.coding.knowledge` because its inclusion was inside the execution-only branch. The shared instruction now appears exactly once in ordinary, claimed and guided coding prompts. `TestCodingModesShareKnowledgeWithoutGuideBodies` failed for guided mode before the repair and passes after it. Guide bodies remain on demand; no guide dump or new tool was added.

**DESIGN-004/005 and CODE-001–009:** the existing standards now ask once about relevant unresolved aesthetic preferences, honor prior choices/delegation, persist a concise project identity, and prefer purposeful handcrafted composition/controls/motion on accessible primitives. Code guidance addresses staged restore, full meaningful outcomes, transition ownership, reset/accounting semantics, bounded-event consumers, real test entry points, negative controls and measured rendering costs. These replace/clarify existing sections; they do not add a compulsory checklist or review stage. Graph section search and role-specific access remain the navigation mechanism. Guide changes are implemented, but improved spontaneous model use and design quality remain empirical acceptance questions.

**NATIVE-001:** duplicate argument keys remain invalid. A well-correlated but ambiguous array is refused in full before effects, with original bytes and one failure receipt per call. The model can issue a new corrected call through the existing bounded run loop; the judge cannot guess a duplicate value. `TestDuplicateArgumentsRefuseWholeArrayAndAllowCorrectedCall` failed before repair and passes with zero refused-array effects and exactly one corrected effect. Uncorrelatable IDs remain fatal. This does not claim recovery for every possible corrupt wire representation.

**RUN-001:** `btw_received` records capture; only successful task-comment persistence plus a durable continuation permits `btw_committed`. The latter means saved placement, not proof the next model request used it. A crash after capture retains an explicitly undelivered note on restore. Historical `btw` events retain their legacy interpretation and are not new committed-delivery evidence. `TestBtwCaptureFailurePreservesPoppedIntentWithoutAcknowledgement` also proves capture I/O failure retains exact Unicode text without an acknowledgement. `TestBtwCommitAcknowledgesPersistedContinuation` checks capture/persistence/ack ordering; existing transcript/steering tests cover model delivery separately.

**WIN-010:** session service lifetime is wired into the existing Bash definition only when a real owner is supplied. Main and child registries share the session owner; headless execution explicitly closes it before exiting. The original ordinary definition remains available without an owner. Integration initially attempted duplicate registration; real CLI tests caught it. A first repair rebuilt visible definitions but lost the hidden legacy `find` registration, which the real TUI request test caught. The final repair replaces only the existing Bash definition in place, preserving compatibility entries, dynamic help and role restrictions. `TestServiceOwnerChangesOnlyOwnedBashAndChildContract` verifies ownership-dependent schema exposure and preservation of unrelated tools. `TestReplacementPreservesCompatibilityAndRoleRestrictions` covers hidden registration and non-widening role views. Check explicitly excludes and refuses service actions before effects; `TestCheckCannotInheritOwnedServiceActions` caught and fixed an asynchronous-check integration defect. No scheduler/startup registration or broad process-kill fallback is introduced.

## Deliberate boundaries

Cross-attempt check receipt reuse is not implemented: current records cannot establish unchanged external/ignored effects or continued execution authority. The existing requeue path preserves the brief and readiness, then requires fresh checks for the new attempt. This is the small safe policy; copying old receipts would violate evidence and ownership principles.

Repeated provider prefill, comparative judge usefulness, model-generated code/design quality, unfinished live feature subflows, actual release asset migration and unsupported-platform qualification remain explicit evidence gaps. They are not fixed by a guide edit, timing from concurrent developer tests, or a passing local package test. No v0.3.0 workflow builder or extra review tier is included.
