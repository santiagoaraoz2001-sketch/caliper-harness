## Parent-owned repairs

- **CODE-021:** inclusive line replacements now refuse a nonempty replacement lacking its final separator when untouched following lines remain. Refusal occurs before publication and preserves the current read/hash, so correction does not require another read. Exact spans, deletion and EOF without a newline retain their literal behavior. Native and text protocol regressions exercise LF/CRLF, refusal bytes, correction and intentional joins. This does not infer which line the user/model intended from a valid hash.
- **PROMPT-002:** check help and the emitted purpose now agree with the existing independent paired stages. Acceptance failure still allows suite evidence; cancellation or receipt-persistence failure stops the episode. Both complete successful exits remain required. No additional check or reviewer is introduced.
- **CLI-001:** README now supplies the existing explicit project-binding operation and explains that binding neither approves work nor makes an approach ready. Ownership validation stays in the lifecycle owner.
- **ASK-002 / GRAPH-009 / GRAPH-011 / GRAPH-013:** canonical instructions clarify parallel answer options and host-provided optional comments, complete-version knowledge updates, role-visible schema help, and historical recall provenance. These support the owning code repairs; wording alone is not evidence of model uptake.
- **REVIEW-001 preventive authority:** reviewers use bounded inspection, saved evidence and the frozen authorized check. Free-form Bash is removed from their actual registry, so a forged shell call cannot mutate project files. Missing reproduction evidence remains UNVERIFIED. The temporary scratch-location mechanism was removed as unnecessary; no new prompt key or custom-catalog migration remains. Frozen check scripts can have side effects, so their binding and post-check project-change guard remain essential.

The existing code/design standards already cover repeated effects, real entry points, state restoration and missing prerequisites. They have not acquired another duplicate checklist. Model-generated artifact findings remain empirical acceptance cases for the fresh run.

## Windows observer boundary

The observer's raw-byte ConPTY transport is test infrastructure, not a new model tool. Its teardown must handle the output channel as well as the child process. Microsoft documents synchronous channel and shutdown deadlocks, including the older-Windows requirement to close or drain the output pipe before closing the pseudoconsole: [session lifecycle](https://learn.microsoft.com/en-us/windows/console/creating-a-pseudoconsole-session), [ClosePseudoConsole](https://learn.microsoft.com/en-us/windows/console/closepseudoconsole). A successful current-machine Unicode burst alone does not qualify older-platform teardown.

## Per-issue integration controls

SCOPE-003 now adds one short rule to existing Bash guidance: scope Git status to the project, resolve porcelain paths against the returned repository root, and treat unborn HEAD as no commit baseline. A real Git repository with an unborn ancestor and a spaced nested workspace proves scoped status excludes a sibling while reporting project paths relative to the ancestor; missing HEAD remains a failing result. The existing project-fingerprint fixture now also proves a sibling edit cannot expand the project scope. This is guidance and a deterministic boundary check, not a guarantee the next model will follow the guidance; no shell rewriting or new judge is introduced.

REVIEW-002 canonical review wording now distinguishes inherited worker claims from the reviewer's own observations and binds interpretation to typed workspace/command/attempt evidence. A deliberate probe from another directory does not establish failure of the pinned check. The lifecycle owner qualifies the actual emitted packet; reported root/receipt mismatch must not be invented from states the check owner already refuses.
